# CloudStorage

**CloudStorage** — веб-приложение для персонального облачного хранения файлов, разработанное на Java с использованием Spring Boot.

Приложение позволяет регистрироваться, авторизоваться, загружать файлы на сервер, просматривать список загруженных файлов и скачивать их обратно.

### Работающее приложение

**https://cloud.peremuchka.space**

### Технологический стек

| Технология | Назначение |
|---|---|
| Java 21 | Основной язык разработки |
| Spring Boot 4.1.1 | Серверное приложение |
| Spring MVC | Обработка HTTP-запросов |
| Spring Security | Аутентификация и управление доступом |
| Thymeleaf | Серверный рендеринг HTML |
| Spring JDBC / JdbcTemplate | Выполнение SQL-запросов |
| PostgreSQL 17 | Хранение пользователей и метаданных файлов |
| Docker / Docker Compose | Контейнеризация приложения |
| GitHub Actions | CI/CD |
| Nginx | Обратное проксирование |
| Let's Encrypt | HTTPS-сертификат |

## Функциональность

- Регистрация новых пользователей.
- Авторизация с использованием HTTP-сессий.
- Хеширование паролей алгоритмом BCrypt.
- Загрузка файлов через веб-интерфейс.
- Просмотр списка собственных файлов.
- Скачивание файлов.
- Ограничение доступа к файлам по владельцу.
- Защита форм от CSRF.

## Архитектура

Приложение разделено на несколько логических слоёв:

- **Controller** — обработка HTTP-запросов, получение параметров, возврат представлений и HTTP-ответов.
- **Service** — бизнес-логика регистрации и работы с файлами.
- **Repository** — взаимодействие с PostgreSQL через JdbcTemplate.
- **DTO** — передача данных между компонентами приложения.
- **Configuration** — настройка Spring Security и других компонентов Spring.

### Хранение файлов

Содержимое файлов сохраняется в файловой системе под уникальными именами, сформированными с помощью UUID.

PostgreSQL хранит метаданные: идентификатор файла, владельца, исходное имя, ключ хранения, размер и дату загрузки.

При скачивании проверяется принадлежность файла авторизованному пользователю.

## Локальный запуск

Требования: Java 21, Docker с Docker Compose и доступ к Maven Central.

1. Клонировать репозиторий:

```bash
git clone https://github.com/NARIMANGUS/CloudStorage.git
cd CloudStorage
```

2. Создать файл `.env`:

```dotenv
DB_PASSWORD=local_dev_password
```

3. Запустить PostgreSQL и создать таблицы:

```bash
docker compose up -d postgres

docker compose exec -T postgres \
  psql -U cloud_user -d cloudstorage < db/init.sql
```

4. Собрать приложение и запустить контейнеры:

```bash
SPRING_DATASOURCE_PASSWORD=local_dev_password ./mvnw clean package

docker compose up -d --build
```

Приложение будет доступно по адресу:

http://127.0.0.1:8080

## Развёртывание на VPS

Production-окружение использует `compose.prod.yaml`, включающий:

- Spring Boot backend.
- PostgreSQL.
- Постоянный Docker volume для базы данных.
- Постоянный Docker volume для загруженных файлов.
- Healthcheck PostgreSQL.

Пароль базы данных хранится в `.env` непосредственно на сервере и не включается в Git-репозиторий.

Nginx принимает HTTPS-запросы и проксирует их на backend.

## CI/CD

Автоматическое развёртывание реализовано через **GitHub Actions**.

При отправке нового коммита в ветку `main` выполняются следующие действия:

1. Получение исходного кода.
2. Настройка Java 21 и PostgreSQL для тестов.
3. Сборка проекта и выполнение тестов через Maven.
4. Сборка Docker-образа.
5. Передача образа на VPS по SSH.
6. Обновление и запуск контейнеров через Docker Compose.

Таким образом, обновление приложения осуществляется автоматически после `git push`.

## Безопасность

- Spring Security для авторизации.
- BCrypt для хеширования паролей.
- CSRF-защита.
- Проверка владельца файла перед скачиванием.
- HTTPS через Let's Encrypt.
- Пароли и SSH-ключи не хранятся в репозитории.scenery.updateGeometricState();
